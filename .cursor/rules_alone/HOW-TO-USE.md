# 🎯 ОДИНОЧНЫЕ ИНСТРУКЦИИ

> Инструкции для единичных задач, не входящих в основной flow

---

## 📋 Содержимое

| Файл | Назначение | Как вызвать |
|------|------------|-------------|
| `core-duplicate-check.mdc` | Проверка дубликатов | `@rules_alone/core-duplicate-check` |
| `from-the-end.mdc` | Валидация с конца | `@rules_alone/from-the-end` |
| `ajtbd-evaluation.mdc` | Полный AJTBD-анализ | `@rules_alone/ajtbd-evaluation` |

> **Примечание:** `backlog-to-rules` и `fix-last-task` перенесены в `skills/` (v12.2)

---

## 🔧 Как использовать

### Способ 1: Через @ упоминание (рекомендуется)

```
@rules_alone/core-duplicate-check Проверь есть ли такой компонент
```

### Способ 2: Текстом

```
Используя rules_alone/from-the-end.mdc, проверь задачу с конца
```

---

## 📖 Описание инструкций

### core-duplicate-check.mdc

**Когда:** Перед созданием нового файла/класса/функции
**Что делает:** Ищет похожие по имени и функциональности

### from-the-end.mdc

**Когда:** Сложные задачи с неочевидным результатом
**Что делает:** Требует определить ожидаемый OUTPUT первым

### ajtbd-evaluation.mdc

**Когда:** Анализ лендингов, UI/UX, продуктовых решений
**Что делает:** Полный JTBD-анализ по методологии Замесина

---

## ❓ FAQ

**Чем отличается от rules/?**
Инструкции в `rules/` применяются автоматически.
Одиночные вызываются **только явно**.

**Можно добавить alwaysApply: true?**
**НЕТ.** Это противоречит концепции одиночных инструкций.

**Где backlog-to-rules и fix-last-task?**
Перенесены в `.cursor/skills/` как полноценные skills (v12.2).
